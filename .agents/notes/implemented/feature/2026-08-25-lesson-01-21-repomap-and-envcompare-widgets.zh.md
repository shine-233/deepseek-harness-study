# Agent Note：01 课仓库地图探索器与 21 课三种环境对比器

Status: implemented

[English](2026-08-25-lesson-01-21-repomap-and-envcompare-widgets.md) | 中文

## Problem

路线/看板那一轮之后还剩两节面向初学者的课没有交互模型：01 课（仓库地图）把十行顶层目录表藏在 `<details>` 里，依赖流向只有一张静态 mermaid；21 课（GitHub 网页 / github.dev / Codespaces）第一段就警告「不要把三者的能力混在一起」，紧接着却用一张五栏散文表呈现正是这种风险的内容。

## Decision

两个模块沿用既定组件契约（冻结的逐字数据、导出纯函数、浏览器守卫的 DOM、自注入样式、SPA 路由观察者、按容器门控渲染）：

- `study-repomap.js`：十个目录按钮加详情卡，携带表格两栏原文和一行明确的链路关系（「在运行时依赖主链上」/「不在」）。一个小 SVG 复刻课程自己的 mermaid 链（apps → boot → bundle → packages → core·impl，vendor 虚线）；选中 `apps/`、`packages/` 或 `vendor/` 时对应节点高亮，选其他目录时无任何高亮——图教的是链路成员关系，不是装饰。`chainMember()` 导出，成员标志可测。
- `study-envcompare.js`：三个环境标签；详情卡显示表格四栏原文加课程正文的「能做／不能做」清单。能力矩阵按环境渲染 ✓/✗/—，其中 — 表示「课程没有为网页声称这项能力」；一条测试钉住这条规则，矩阵永远不会漂移成发明。窄屏时矩阵表在容器内横向滚动，不撑宽文档。
- 测试：`study-repomap.test.mjs`（5 条）和 `study-envcompare.test.mjs`（5 条）断言精确的目录/环境序列与能力记号字母表。脚本标签在 `theme/index.ts` 追加。

## Alternatives considered

**让链上每个节点都可点。** 否决：boot 和 bundle 是 `packages/` 的子目录，不是顶层目录；给它们点击目标意味着课程表并不存在的详情数据。

**用一般 GitHub 常识填矩阵的网页一列。** 否决：课程刻意没有为网页声称搜索/编辑能力，而组件引用的正是这门课——发明一个 ✓ 恰恰是课程反对的证据夸大。

**抽一个「按钮组 + 详情卡」公共基座。** 再次否决，理由同前：五个组件现在只共享契约不共享代码，各自保持独立可测，而自然的共享宿主仍在另一条在制工作线里。

## Consequences

首次读者的完整路径（00、01、02、03、04、05、06、07、20、21、26）每课至少有一个交互模型。剩余无组件的课程（08、09、17、18、24、29、30、37）是参考/元页面，其中几篇在另一条在制工作线里。已构建站点实测：十个按钮与三个标签渲染、链路高亮恰好命中三个链上成员、矩阵六行、两页移动端横向溢出 0px、组件测试套件全过；验证时出现的全量失败可追溯到另一工作线的新实验室（provider-lab、credential-lab），与这两个模块无关。
