# Agent Note：trajectory 实验室——事件流从常量变成输入

Status: implemented

[English](2026-08-26-trajectory-scenarios.md) | 中文

## 问题

审计把 trajectory 判为「带播放键的幻灯片」：十四条事件冻结在常量里，唯一的旋钮是重放到第几条，没有分叉、没有假设检验。它教的呈现契约是真的，但页面只能对着一条手工挑选的流演示这个契约。

## 决策

把事件流变成输入，同时保留全部既有契约：

- **四个场景**（`TRAJECTORY_SCENARIOS`）：`canon`（原始 14 条流，与之前逐字节相同）、`unknown-tool`（web_search 突然出现——走保守回退路径）、`interrupted`（Turn 在 chunk 中途死掉，草稿卡永远停在打字中）、`failing-tool`（str_replace 报错但仍按契约结算成 diff 卡）。
- **词表外工具的回退视图**，对齐上游的保守默认：等待态 generic、结果态 generic。此前未知工具会让投影器直接崩掉。
- 校验器新增三条场景专属检查（未知工具回退、打断草稿永不定稿、失败调用照样结算），与既有五条并列；canon 的重放边界循环跳过对它不适用的场景检查。
- 视图：表单加入场景下拉；步进滑杆的上限跟随组合出的流长度并在切换时收敛；状态 hash 携带场景。

## 考虑过的替代方案

自由编辑事件 JSON——否决：那会把实验室变成调试器，还招来远离教学点的畸形输入。四个精选场景以零非法输入保证覆盖契约的每个分支。同一轮顺带重写 subagent-delegate——推迟：它值得一个自己的生成树模拟和自己的 Agent Note。

## 后果

trajectory.test.mjs 原有五条测试逐字保留、新增三条场景测试（本文件 23 条；study-tools 全套 860 条）。按审计分类学，这个实验室从回放移向模拟：用户现在可以扰动输入流，看着呈现契约作出反应。课程正文未动——05 课对这只投影视角的描述本来就是对的。
