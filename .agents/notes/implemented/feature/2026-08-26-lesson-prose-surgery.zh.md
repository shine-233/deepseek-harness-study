# Agent Note：课程文案手术——砍跨页复读，修概念跳步

Status: implemented

[English](2026-08-26-lesson-prose-surgery.md) | 中文

## 问题

全书审计（38 课逐页读完，叠加机械的 `audit-ai-flavor` 报告）发现三类脚本查不了的系统性缺陷：20/26/32 课有整节在用压缩指针复述 10–19 和 27 课拥有的内容；五处概念跳步，术语未介绍就使用（03 的 subagent、14 的瀑布不变式、05 的「切面／单元名」、07 的三个名词化指针、23 的官方类型名）；同一条证据边界免责声明在一页内重复多达三次（23、32）。

## 决策

事实归别的页管的就砍掉；没有其他归宿的命题一条不留地保住。

- **第 20 课**（散文 −39%）：四步首用流程压成一段；六段「怎样学写插件」只留两条硬规则（每加一项要清理的资源就同时加取消和清理测试；证据层级不能越级替代）加逐课指针；四段社区审核指南收缩为它独有的规则——把「项目 README 自称通过」和「你实际运行的命令」记成两栏——核对清单本身交给 12 和 27。
- **第 32 课**：三重免责合并成一句带复核日期的开场；实验室链接段移到它所说的「上面路径」之下（原来悬在路径图上方）；首页状态条一句不再引用写死的计数——数字会漂移，门禁输出才是权威。
- **第 26 课**：「组件打到循环哪一层」一段（与 32 课表格逐字重复）改成指针；四段方法论压成两段，每条可操作的规则都在：边际收益框架、「机制可验证但结论不可推广」缺口、混杂因素清单、A/B 属因果比较。
- **跳步修复是加内容而不是删**：03 在讲深度上限前先交代什么是 subagent 委派；14 先解释什么叫瀑布派发再陈述不变式，并链到 02 课；05 用平实语言说清存储契约（必需 kv 能力缺失就在解析点报错；单元名同时当文件名和 SQL 标识符），不再甩术语；07 把三个名词指针全部兑现成真实契约内容——plan-review 的五个接管条件（意图声明、单问题、二元单选、批准标签、detail 附计划）取自 `client-model.js`，不是编的；23 给 `ToolProviderResult.schemas`/`knownNames` 补上与上方分层表的对应关系。
- **免责收敛只动已经碰过的页面**（23：同页三条 → 两条；32：三条 → 一条）。全书范围清除被否决：学习体验契约门禁检查其中多处措辞，这种重复本身就是仓库证据边界纪律的一部分。
- **金句锤结尾**：16/17 保留——各自直接总结紧上方的操作步骤；改强文本本身是一种失败。只有 23 的结尾重写，点名它的具体产物（一份含环境、数字和未证明项的 A/B 记录模板）。

## 考虑过的替代方案

合并 START-HERE/16/25（同一件事讲三遍）——推迟：START-HERE 正在被并行修改，且入口页合并必须在同一改动里迁移学习体验契约门禁的期望。
全书清扫约 100 条边界免责——因上述门禁原因否决；页内收敛已拿到可读性收益，不必和质量体系对着干。
重写 37 课的单薄源码覆盖——留给正在落地的零跳步阶梯实验。
