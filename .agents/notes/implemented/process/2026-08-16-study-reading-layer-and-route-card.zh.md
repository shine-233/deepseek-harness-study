# Agent Note: 学习阅读层与路线卡

Status: implemented

[English](2026-08-16-study-reading-layer-and-route-card.md) | 中文

## 问题

学习网站已经有明确的入口、完整的课程和文件索引侧栏，但阅读界面没有把短路线与完整目录区分出来。长篇课程也需要更明显的当前页面、本页目录、代码、表格和移动端提示，同时不能修改 canonical Markdown 或生成投影。

## 决定

中文源码学习侧栏在完整课程和索引分组之前增加一个小型 `阅读路线` 分组，包含已发布的开始页、15 分钟任务单、工具与插件决策卡和文件索引入口。`studyPageLink` 从 `docsPages` 解析这些链接，因此路线卡跟随发布 manifest，而不是维护第二套生成文件名。

网站通过 `website/public/reading.css` 加载只负责呈现的样式层。它为标题提供滚动偏移，为正文提供可读节奏，强化当前侧栏项和本页目录，处理代码与表格的溢出，固定表头，增加键盘焦点环，并收紧移动端首页和文档间距。该层继续使用 VitePress 默认的导航、首页、本页目录、页脚和搜索组件，不增加客户端状态、不复制 canonical 文案，也不从浏览器存储推断完成度。

## 考虑过的替代方案

**给课程页增加进度状态。** 已否决：完成状态需要持久化以及“完成”的定义，而 canonical 学习材料没有提供这两者。路线卡只负责定位，不声称学习进度。

**用硬编码的公开 URL 维护路线卡。** 已否决：生成课程路由会按源文件名编码，因此 manifest 变更后硬编码链接可能漂移。路线卡通过 `docsPages` 和 `routeLink` 按源文件解析。

**移动或改写 canonical Markdown 来实现视觉处理。** 已否决：`website/` 只拥有配置和呈现资产，学习正文仍属于 `study/`，首页正文仍属于根目录的 canonical 文件。CSS 层保持这个归属边界。

## 影响

第一次进入中文源码学习的读者会先看到一条短路线，同时仍可使用完整侧栏和默认上一篇/下一篇链接。表格在窄屏上仍可横向阅读，代码仍由 VitePress 默认控件负责复制，键盘焦点清晰可见。网站不会显示数字化课程完成率、跨设备同步进度，也不会证明读者完成了任何课程。

样式依赖 `VPSidebarItem`、`VPHome` 和 `VPDocAsideOutline` 等 VitePress 默认主题类名；构建会验证资源可交付和页面可渲染，但未来升级 VitePress 主版本仍需要人工视觉复核。
