# Agent Note: 学习网站美化与发布路线契约

Status: implemented

[English](2026-08-17-study-site-polish-and-publish-contract.md) | 中文

## Problem

学习网站已经有引导首页和最小示例，但第一次阅读路线仍然只在源文件 manifest 层面检查。某个路线即使存在于 Markdown 和 VitePress manifest 中，也可能在最终的 `website/.dist` 里缺少发布页面或阅读样式资源。固定提交路径检查器还把学习站专用资源误当成官方 DSH 源码路径；双语示例链接如果指向中文 README，也会因为结构比较过于字面而失败。

## Decision

根 VitePress 导航现在给中文源码学习路线提供直接的“开始学习”入口、最小示例入口、学习工具箱入口和逐文件索引入口。网站增加本地化页脚、最后核对标签、GitHub 反馈链接和已纳入版本控制的阅读样式表，同时继续使用默认 VitePress 主题。这些只是呈现层变化；仓库仍然是静态 Pages 网站，没有新增 API、数据库或运行时后端。

学习入口把第一轮拆成“约 5 分钟认识六个词和仓库地图”以及“约 15 分钟留下固定版本源码记录”，并把入口、快照、A/B、索引和发布检查集中到[学习工具箱](../../../../study/31-学习工具箱.md)。中文导航直接提供工具箱和逐文件索引入口；示例 README 与课程统一从仓库根目录复制命令，并写明预期退出状态和练习复位方式。

`study-tools/verify-built-study-site.mjs` 为首页、START-HERE、示例目录、最小观察页和示例课程定义了一份小型发布路线契约。它检查稳定的语义文案标记，以及 `reading.css` 和 `favicon.svg`；它的单元测试覆盖完整产物，也分别覆盖缺页、缺标记和缺资源。`docs:build` 会在 fragment 校验器之后运行这项检查，所以构建成功还意味着第一次阅读路线确实被输出了。

随后，`study-tools/verify-study-publication.mjs` 读取生成投影中的 `editSource` 元数据，枚举全部中文学习页面（课程、文件索引页、START-HERE、学习工具箱和示例页），确认每页都有构建后的 HTML 和 H1，并把同站学习链接对照构建后的路由别名检查。它是路由覆盖检查，不声称真人已经读完每一段，也不声称运行时插件已经工作。

固定提交路径校验器只豁免明确列出的、归学习仓库所有的 `website/public/reading.css` 和 `website/.dist`；其它 `website/...` 路径仍然接受官方 tree 检查。双语配对签名在比较指向对应 `.md` 文档的链接时，只把末尾 `.zh.md` 后缀规范化；锚点、查询参数和不同目标仍然严格比较。这样中文示例可以指向中文 README，同时不会削弱普通的链接漂移检查。

## Alternatives considered

**增加服务端学习后端。** 否决，因为内容是静态的，读者可以从 GitHub Pages 开始，而新增服务只会带来部署、凭据和运行时失败模式，并不能帮助第一次源码阅读练习。

**对生成后的整套 HTML 做快照。** 否决，因为 VitePress 和 Shiki 合理地改变标记结构和资源 hash。稳定的页面契约和语义标记既能抓住路由回归，也能允许无害的视觉重新构建。

**忽略所有 `website/` 下的缺失路径。** 否决，因为这样会掩盖官方 DSH 网站源文件的拼写错误。豁免范围只限于导致误报的两个、归学习仓库所有的路径。

**强制两种语言都链接到英文 README。** 否决，因为中文学习路线应当保持中文优先。配对检查器现在理解狭窄的语言后缀等价关系，同时继续比较真实目标、锚点和查询参数。

## Consequences
新增的学习体验契约也会在 Pages 构建前检查：首页、START-HERE、关键课程和两个中文示例 README 必须明确写出新手要做什么、应该看到什么以及这一步没有证明什么。它是内容存在性检查，不是理解度、浏览器、真实 DSH 或模型运行测试。

第一次阅读者会看到更少的竞争性导航选择，有一条明显的反馈路径和一个不会启动 DSH 的工具箱入口；构建过程也会检查这条路线背后的页面和资源确实被输出。生成站点检查仍然不能证明浏览器点击、响应式可访问性、真实 DSH Loader、provider 调用、模型质量、插件卸载或安全性。这些仍然是教材中分开的证据层级。已提交的网站有意保持为静态投影链：Markdown 和源码 manifest 输入 VitePress，构建生成 `.dist`，GitHub Pages 提供该产物。
