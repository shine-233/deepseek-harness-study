# 从零开始读 DSH

这是一份给第一次读大型程序的人准备的路线图。你不需要先记住所有英文名；先把 DSH 想成一个“能让模型工作、调用工具、保存过程、让插件替换零件”的程序。

## 先记住六个词

- **插件**：可以插入或拔出的功能模块。DSH 里模型、工具、会话和界面都可以是插件。
- **服务**：插件放进共享上下文后，其他插件可以取得的能力，例如 `ctx.sessions` 或 `ctx.tools`。
- **事件**：插件之间发消息的方式。发送者不必知道所有接收者，因此新功能可以旁路接入。
- **Profile**：一次运行使用哪几层功能的名单，像一张装配清单。
- **Bundle**：一层可安装的功能组合，通常通过补丁把很多插件放进树里。
- **Turn 与 Step**：一次用户目标叫一个轮次；轮次里面每次模型请求和它调用的工具组成一个步骤。

## 推荐阅读顺序

1. 读[仓库地图](01-仓库地图.md)，知道文件在哪一层。
2. 读[Cordis 与插件树](02-Cordis与插件树.md)，理解 `Context`、服务、事件和可撤销效果。
3. 读[核心文件精读](03-核心文件精读.md)，只先读列出来的主链路文件。
4. 读[Agent 与 Turn 流程](04-Agent与Turn流程.md)，把一次请求按时间顺序串起来。
5. 读[Session 日志与恢复](05-Session日志与恢复.md)，理解为什么事件要持久化。
6. 读[LLM 与工具执行](06-LLM与工具执行.md)，理解模型输出怎样变成工具调用。
7. 最后打开[逐文件索引](08-逐文件索引怎么读.md)，按兴趣跳到 2,756 个文件中的任何一个。

## 一个最小的心智模型

可以把一次请求画成：

```text
用户输入
  -> Agent 收到输入
  -> Session 记录输入
  -> Prompt 组装上下文和工具说明
  -> LLM 产生流式回答
  -> Agent 判断是否要调用工具
  -> Tool 执行并返回结果
  -> Session 记录结果
  -> 需要时进入下一步，否则结束 Turn
```

这里的箭头不是某一个函数直接调用所有东西，而是许多插件通过服务和事件连接起来。读源码时要问两件事：这条信息在哪里产生，最后由谁消费；这项能力是稳定接口，还是某个可替换提供方。

## 怎样读一个文件

先读文件所在包的 README，再读 `index.ts` 入口，然后看类型和事件，接着看实现，最后看同包测试。遇到一个名字时，不要只看它“做了什么”，还要看它为什么没有放进另一个文件：通常答案是边界、替换、测试或生命周期。

## 读到不懂时怎么办

不要从一个 2,000 行文件的第一行硬读到最后。先从[核心精读](03-核心文件精读.md)中的文件开始，再顺着“直接协作者”和测试链接跳转。索引中标为“自动索引”的条目只提供方向；涉及行为时必须回到固定版本源码核对。
